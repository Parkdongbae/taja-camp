# 3. 연습 콘텐츠·DB 스키마

> 목적: 자리·낱말·단문·장문 콘텐츠와 학생 데이터의 구조, 난이도 기준, 접근 권한을 확정한다.

## 1. 저장 위치 한눈에 보기

| 데이터 | 저장 위치 | 이유 |
|---|---|---|
| 자리연습 단계 정의·자판 배열 | 코드 저장소 (`src/data/*.ts`) | 바뀌지 않는 고정 데이터 |
| 기초 콘텐츠(낱말·쉬운 문장) | 코드 저장소 (`src/content/builtin.ts`) | 직접 새로 쓴 글만 앱에 내장 |
| 교과 낱말·단문·장문 콘텐츠 | **Firestore `content/*` 조각 문서** (로그인한 사용자만 읽기). 교사가 선생님 모드 "콘텐츠 올리기"에서 JSON 파일을 올려 저장 | 교과서 기반 자료라 공개 저장소에 올리지 않기 위해(→ 8장) |
| 학생·기록·순위 | Firestore (`students`, `sessions`). 순위표는 `students` 를 직접 읽음 | 조회·정렬·권한 관리 |
| 배틀 방·실시간 상태 | Realtime Database (`presence`, `rooms`) | 초 단위 동기화, 접속 끊김 감지 |
| PIN 해시 | Firestore `secrets/{sid}` (보안 규칙으로 클라이언트 읽기 불가) | 클라이언트 노출 금지 |
| 교과서 원본 PDF/HWP, 추출 콘텐츠 | 로컬 `교과서자료/`, `content-data/` 폴더만 (`.gitignore`) | 저작물 원본과 추출본은 깃허브에 올리지 않음 |

## 2. 콘텐츠 스키마

### 2.1 공통 필드

```ts
type Subject = 'korean' | 'english' | 'math' | 'science' | 'social';
type Lang    = 'ko' | 'en';
type Level   = 1 | 2 | 3;          // 쉬움 / 보통 / 어려움

interface ContentBase {
  id: string;                      // 예: "w-sci-0123"
  lang: Lang;                      // 입력 언어 (영어 과목만 'en')
  subject: Subject;
  unit: string;                    // 단원명. 예: "Ⅱ. 생물의 구성과 다양성"
  level: Level;
  strokes: number;                 // 타수(1번 문서 2.2 기준으로 자동 계산)
  usedKeys: string[];              // 필요한 글쇠 코드 목록 (자동 계산)
  source: string;                  // 출처. 예: "사회 9단원"
  active: boolean;                 // 교사가 끌 수 있음
}
```

### 2.2 낱말 (`content/*` 조각 문서에 묶어 저장)

```ts
interface WordItem extends ContentBase {
  text: string;                    // "광합성", "지구 온난화", "environment"
  meaning: string;                 // 뜻풀이(영어는 우리말 뜻). 40자 이내
  wordCount: 1 | 2;                // 배틀 점수용 (띄어쓰기 기준)
  homeRowOnly: boolean;            // 기본자리 글쇠만으로 된 낱말인가 (배틀 1점)
  battle: boolean;                 // 배틀 출제 여부 (2~8음절만)
}
```

### 2.3 단문 (`content/*` 조각 문서에 묶어 저장)

```ts
interface SentenceItem extends ContentBase {
  text: string;                    // 한 문장, 15~50자
  keywords: string[];              // 문장에 든 교과 용어 (낱말 id 연결)
}
```

### 2.4 장문 (`content/*` 조각 문서에 묶어 저장)

```ts
interface PassageItem extends ContentBase {
  title: string;                   // "민주주의란 무엇인가"
  lines: string[];                 // 화면 한 줄(최대 38자) 단위로 미리 나눈 본문
  charCount: number;               // 300~600자
  estMinutes: number;              // 150타/분 기준 예상 소요 시간
}
```

### 2.5 자리연습 (코드 내 고정 데이터)

```ts
interface PositionStage {
  id: 'K1'|'K2'|'K3'|'K4'|'K5'|'K6'|'K7'|'K8'|'S1'|'S2'|'E1'|...|'E7';
  track: 'ko' | 'symbol' | 'en';
  order: number;
  name: string;                    // "기본자리"
  newKeys: KeyTarget[];            // 이 단계에서 새로 배우는 글쇠
  drills: string[][];              // 익히기용 묶음. 예: ["ㅁ","ㄴ","ㅇ","ㄹ"], ["ㅓ","ㅏ","ㅣ"]
}

interface KeyTarget {
  code: string;                    // KeyboardEvent.code. 예: "KeyS"
  shift: boolean;
  label: string;                   // 화면 표시 글자. 예: "ㄴ", "@"
  finger: 'L5'|'L4'|'L3'|'L2'|'R2'|'R3'|'R4'|'R5'|'T'; // 손가락(L5=왼손 새끼)
}
```

자리연습 문항은 저장하지 않고 단계 정의에서 **매번 생성**한다(같은 글쇠 3회 연속 금지, 왼손·오른손 번갈아 나오도록 가중).

## 3. 난이도 기준

난이도는 사람이 매기지 않고 아래 규칙으로 자동 계산한다. 교사가 개별 수정할 수 있다.

### 3.1 낱말

| 수준 | 기준 |
|---|---|
| 1 쉬움 | 2~3음절, 받침 1개 이하, 겹모음·겹받침·쌍자음 없음 (예: 세포, 지도) |
| 2 보통 | 3~4음절 또는 겹모음·쌍자음 1개 포함 (예: 광합성, 민주주의) |
| 3 어려움 | 5음절 이상, 두 단어, 겹받침·Shift 글쇠 2개 이상 (예: 지구 온난화, 읽기 전략) |

영문 낱말: 1 = 3~5자, 2 = 6~8자, 3 = 9자 이상 또는 대문자·하이픈 포함.

### 3.2 단문

| 수준 | 타수 | 추가 기준 |
|---|---|---|
| 1 | 30~50타 | 문장부호는 마침표만 |
| 2 | 51~80타 | 쉼표·숫자 포함 가능 |
| 3 | 81~120타 | 따옴표·괄호·기호·영문 혼용 포함 |

### 3.3 장문

| 수준 | 글 길이 | 성격 |
|---|---|---|
| 1 | 300자 안팎 | 짧은 문장 위주 설명글 |
| 2 | 400~500자 | 교과 개념 설명글 |
| 3 | 500~600자 | 숫자·기호·인용이 섞인 글 |

### 3.4 학생 수준별 출제

| 학생 상태 | 낱말·단문 출제 비율 (1 : 2 : 3) |
|---|---|
| 한글 타수 100타 미만 | 70 : 30 : 0 |
| 100~200타 | 30 : 50 : 20 |
| 200타 이상 | 10 : 40 : 50 |

- 자리연습을 마치지 않은 학생에게는 **이미 배운 글쇠만으로 된 낱말**(`usedKeys` 로 판별)을 우선 출제한다.
- 최근 틀린 글쇠가 든 낱말의 출제 확률을 2배로 올린다(약점 보강).
- 같은 항목은 최근 50개 안에서 다시 나오지 않는다.

| **합계** | **690** | **300** | **36** | |

제작 절차

```
① 교과서 PDF → 텍스트 추출 (단원별)
② AI 가 교과 용어 후보·교과서 원문 발췌 문장 후보 선별 + 뜻풀이 작성
③ 자동 검사: 타수·난이도·usedKeys 계산, 자판으로 못 치는 글자 치환, 중복 제거, 금칙어
④ 사람(교사) 검수: 표로 출력해 오탈자·부적절 항목 확인
⑤ 결과를 `content-data/` 의 JSON 으로 저장 → 교사가 선생님 모드 "콘텐츠 올리기"에서 업로드(Firestore 저장)
```

## 5. 사용자 데이터 스키마 (Firestore)

```
students/{sid}                       ← 문서 ID = 학번 (예: "1315")
  name: string
  grade: number, classNo: number, number: number    // 학번에서 분해
  createdAt, lastLoginAt: timestamp
  position: {
    ko:     { stage: 4, best: { K1: 100, K2: 96, K3: 92 } },   // stage = 현재 도전 단계
    symbol: { stage: 0, best: {} },
    en:     { stage: 1, best: {} }
  }
  battleUnlocked: boolean
  rank: { tier: 0~5, rp: number, wins: number, games: number }
  best: { koKpm: number, enKpm: number, koAcc: number, enAcc: number }
  totals: { seconds: number, days: number, streak: number, lastDay: "2026-11-22", xp: number, weeklyGain: number }
  quizPoints: number                 // 뜻 맞추기 퀴즈 누적 점수. 옛 문서에는 없을 수 있어 0 으로 읽는다
  exam?: { ko?: ExamResult, en?: ExamResult }   // 수행평가 언어별 인정 기록. 응시 전에는 없음
  // ExamResult = { kpm, accuracy, typos, grade: 'A'~'E', attempts(응시 횟수), at(인정 기록 시각), passageTitle? }
  weakKeys: { [code: string]: { miss: number, hit: number } }   // 최근 누적
  badges: string[]

secrets/{sid}                        ← PIN 해시. 클라이언트 읽기 불가(규칙)
  pinHash: string                    // SHA-256. 첫 접속 때 학생이 PIN 을 정하면 생성, 초기화는 교사가 문서 삭제

links/{uid}                          ← 익명 로그인한 학생이 자신을 증명하는 문서(uid = Firebase 익명 계정)
  sid: string, name: string, pinHash: string
  // 규칙이 students/{sid} 의 이름과 secrets/{sid} 의 pinHash 가 일치할 때만 생성을 허용

sessions/{autoId}                    ← 연습 1회 기록
  studentId, classNo
  mode: 'position' | 'positionTest' | 'word' | 'sentence' | 'passage' | 'quiz' | 'exam'
  lang: 'ko' | 'en', subject?: Subject, stageId?: string
  kpm, accuracy, typos, strokes, seconds
  score?: number                     // 승급 테스트 점수, 퀴즈 한 판 점수
  passed?: boolean
  missKeys: { [code: string]: number }
  createdAt: timestamp

teachers/{uid}                       ← Firebase Auth 교사 계정(이메일/비밀번호)
  email, name, role: 'admin' | 'teacher'

config/owner                         ← 처음 가입한 교사가 만들면 그 교사가 관리자
  uid: string

invites/{email}                      ← 관리자가 초대한 교사 이메일
  email, invitedBy: uid, createdAt

settings/global
  battleEnabled: boolean, dailyGoalMinutes: 10, passScore: 90,
  testSecondsPerItem: 3, rankingPublic: boolean,
  exam: { open: boolean, langs: ('ko'|'en')[], minutes: 3, maxAttempts: 2,
          passageKo: string|'random', passageEn: string|'random', title: string },   // 옛 문서에는 없을 수 있어 기본값과 합친다
  tierThresholds: [0, 100, 300, 600, 1000, 1500], semester: "2027-1"

content/{조각 id}                    ← 낱말·단문·장문 항목을 수십~수백 건씩 묶은 조각 문서(교사가 JSON 으로 올림)
```

- `publicProfiles`·`studentSecrets`·`battleResults` 컬렉션은 없다. 순위표는 `students` 를 직접 읽는다(로그인한 학생·교사만 읽기 가능). 배틀 결과는 저장하지 않고 `claims` 로 계산한다.

필요한 복합 색인

| 컬렉션 | 색인 | 용도 |
|---|---|---|
| students | `rank.rp desc` / `classNo asc, rank.rp desc` | 배틀 순위 |
| students | `best.koKpm desc` / `classNo asc, best.koKpm desc` | 타수 순위 |
| students | `quizPoints desc` / `classNo asc, quizPoints desc` | 퀴즈 순위 |
| sessions | `studentId asc, createdAt desc` | 내 기록 |
| sessions | `classNo asc, createdAt desc` | 교사 현황 |

## 6. 실시간 데이터 스키마 (Realtime Database)

```
presence/{sid}:   { name, classNo, tier, doing: "word", at: serverTime }

rooms/{roomId}:
  meta:    { tier, host, state: "waiting"|"playing"|"done", seed, startAt, durationSec: 120, lang: "ko", createdAt }
  players: { [sid]: { name, joinedAt, online } }
  claims:  { [wordIndex]: { by: sid, at: serverTime } }   ← 트랜잭션으로 선점
```

- 방 정원은 16명이다. 같은 계급에 접속자가 16명을 넘으면 방이 여러 개 생긴다.
- 방은 경기 종료 후 마지막으로 나가는 클라이언트가 지운다(접속 끊김은 `onDisconnect` 로 처리).
- `presence` 는 교사의 실시간 현황 화면과 배틀 로비의 접속 인원 표시에 쓴다.

## 7. 접근 권한 (보안 규칙 요약)

서버 함수·Firebase Admin·맞춤 토큰은 쓰지 않는다. 권한은 Firestore·Realtime Database 보안 규칙만으로 강제한다.

- 학생: Firebase 익명 로그인 후 `links/{uid}` 문서(`sid, name, pinHash`)를 만들어 자신을 증명한다. 규칙이 `students/{sid}` 의 이름과 `secrets/{sid}` 의 PIN 해시가 일치할 때만 생성을 허용한다. 이후 규칙은 `links/{uid}.sid` 로 "본인"을 판별한다.
- 교사: 이메일/비밀번호 로그인(`teachers/{uid}`). 처음 가입한 교사가 `config/owner` 를 만들어 관리자가 되고, 관리자가 `invites` 에 다른 교사의 이메일을 올려 초대한다.

| 데이터 | 학생 | 교사 |
|---|---|---|
| `content/*` | 읽기 | 읽기·쓰기 |
| `students/{본인}` | 읽기. 쓰기는 규칙으로 제한: 이름·학번 불변, RP 감소 불가·1회 +80 이하, 자리 단계 감소 불가·1회 +1 이하, 퀴즈 점수 감소 불가·1회 +220 이하, 타수 0~1500 | 읽기·쓰기 |
| `students/{타인}` | 읽기(순위표용). 쓰기 불가 | 읽기·쓰기 |
| `secrets/{sid}` | 읽기 불가. 문서가 없을 때만 생성(첫 접속 PIN 설정) | 읽기 불가. 삭제(PIN 초기화) |
| `links/{uid}` | 본인 것 읽기. 생성은 `students`·`secrets` 와 일치할 때만 | 읽기 |
| `teachers/*`, `config/owner`, `invites/*` | 불가 | 처음 가입한 교사만 `config/owner` 생성. 나머지는 관리자만 쓰기 |
| `sessions` | 본인 것 만들기·읽기(값 범위 검증) | 읽기 |
| `settings/global` | 읽기 | 읽기·쓰기 |
| RTDB `presence/{본인}` | 본인 것 쓰기 | 읽기 |
| RTDB `rooms/{room}/claims` | 참가자만, 빈 칸에만, `by == 본인` | — |
| 단계 승급·RP·계급 | 클라이언트가 계산해 본인 문서에 쓰고 규칙이 범위 검증 | 수동 조정 |

## 8. 저작권·개인정보 유의 사항

| 항목 | 방침 |
|---|---|
| 교과서 원본 파일·추출 콘텐츠 | 깃허브에 올리지 않는다(`.gitignore` 에 `교과서자료/`, `content-data/`). 원본은 파일 크기도 깃허브 제한(100MB)을 넘는다 |
| 낱말 | 교과 용어 자체는 자유롭게 사용. 뜻풀이는 새로 쓴다 |
| 단문·장문 | **교과서 원문 발췌**로 구성한다(교육 목적) |
| 콘텐츠 공개 범위 | 교사가 선생님 모드 "콘텐츠 올리기"에서 JSON 파일을 올려 Firestore 에 저장하고, 로그인한 학생·교사만 읽는다. 앱에는 직접 새로 쓴 "기초" 콘텐츠만 내장한다. 깃허브 저장소는 공개이므로 README 등 공개 파일에는 교과서 관련 내용을 적지 않는다 |
| 학생 개인정보 | 학번·이름만 수집. 순위표에는 반·이름·계급만 표시. 학기 종료 시 교사가 일괄 삭제할 수 있다 |
